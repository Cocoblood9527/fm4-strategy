# 雷霆任務4 攻略 · 数字化检索站

把一本 **2003 年的纸质游戏攻略书**（《雷霆任務4 故事完全攻略》，疾風之狼文化事業有限公司出版）的扫描版，转换成现代排版、可全文检索、可排序筛选数值表的静态网站。

## 为什么不是"把 PDF 转成网页"就完事

原书是**纯扫描稿，零文字层**——178 页每页一张 JPEG。所以整件事的成败取决于 OCR，而两种引擎的能力差异极大，且不是"谁更强"而是"各管一段"：

| 内容类型 | 结果 |
|---|---|
| 正文／剧情／角色介绍 | 近乎全对 |
| 数值表格（武器／零件／背包／技能） | 传统 OCR 完全崩溃，需要版面引擎的结构化输出 |
| 金手指 PC 码 | 单个字符 `0`/`O` 错判就会让码失效，必须逐字校验 |
| 战场地图 | 本质是图，只能保留为图像 |

因此采用**双引擎分工**：

- **MinerU**（主干）→ 表格 HTML、段落合并、标题层级、图片 bbox、页眉页码
- **macOS Vision OCR**（兜底）→ 仅在 MinerU 未取到关卡名/文字时补名，并作为交叉校验

关键一点：**页眉里的关卡名在 MinerU 里属于 `discarded_blocks`**，按常规做法会被直接丢弃，但它恰恰是导航树最可靠的来源（30 关的 STAGE 号与地名全在这里）。

## 站点的三层结构

1. **结构层** — 侧栏导航树。非攻略篇的分节直接用原书目录页的印刷页码切分（权威）；攻略篇用多信号融合检测关卡边界：地图块 + 胜负条件文字 + 页眉关名，且关卡名横幅的判定用「位于地图块上方」这一**相对**判据，而非绝对坐标（原书有整页版式偏移的情况）。
2. **内容层** — 正文重排为响应式语义 HTML；数值表转成可点表头排序、可关键字筛选的数据表；地图与截图按 bbox 自动裁切后保留。
3. **证据层** — 每个内容块都能一键调出原扫描页并**高亮对应区域**，同时附该页未校对的 OCR 原文。这让残留的识别错误可被自查，而不是被静默呈现为"正确答案"。

检索支持**简繁与译名别名互通**（你习惯用简体，原书是繁体）：输入「敌方机体 加农炮」可命中「敵方機體資料」表格，「步枪 重量」可命中「來福槍」表。别名表在 [site/data/aliases.json](site/data/aliases.json)，是我手写的原创数据。

## 本地运行

站点数据已在仓库内，克隆后直接起服务即可：

```sh
cd site && python3 -m http.server 8765
# 打开 http://127.0.0.1:8765/index.html
# 必须走 http，file:// 下 fetch 会被浏览器拦
```

若要**重新构建**（改动解析规则、补充转录），需要两个只存在本地、未纳入版本控制的输入：
原始扫描 PDF，以及 MinerU 的 `middle.json`。逐页 WebP 由 PDF 重新压缩生成，Vision OCR 结果在 `_analysis/json/`。

```sh
python3 tools/build.py     # 重生成 site/data/*.json 与裁切图
```
